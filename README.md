# 책잇 — 책 교환 웹앱

## 실행

Node.js 20 이상에서 이 폴더를 열고 `node server.mjs` 실행 후 http://127.0.0.1:4173 에 접속하세요. 설치 또는 빌드가 필요 없습니다.

## 데모 이용

로그인 화면의 ‘서연으로 체험’과 ‘초록책장으로 체험’을 번갈아 사용하면 같은 브라우저에서 신청 → 수락 → 연락처 확인 → 메모 → 양쪽 완료를 체험할 수 있습니다. 이메일로 새 계정도 생성할 수 있습니다. 테스트 시 임의의 체험용 정보만 입력하세요.

데이터는 `bookit.demo.v1`, 현재 세션은 `bookit.session` 키로 localStorage에 저장됩니다. 다른 기기나 브라우저와 동기화되지 않습니다. 저장 공간이 부족하면 오류와 함께 변경을 되돌립니다.

## 구조 및 실제 서비스 전환

- `dist/app.js`: 라우팅, 폼, 데모 인증 및 저장소 어댑터 역할. 이메일 인증은 솔트와 SHA-256을 사용한 로컬 데모이며 실제 사용자 인증 시스템이 아닙니다.
- `dist/domain.js`: 데모 초기 데이터, 추천 함수, 신청 생성, 상태 전환, 연락처 접근 정책. 실제 AI 연결 시 `recommend`를 교체합니다.
- `dist/style.css`: 모바일 반응형 디자인.
- `test.mjs`: `node test.mjs`로 도메인 테스트 실행.

운영 전에는 인증·저장소를 서버 API로 교체하고, 서버에서 교환 당사자 권한을 검증해야 합니다. 현재 연락처는 UI에서 수락된 교환 당사자에게만 표시하지만, localStorage 자체는 개발자 도구로 읽을 수 있으므로 서버 수준의 개인정보 보호를 제공하지 않습니다. 실제 개인정보를 넣는 공개 서비스로 사용하면 안 됩니다. 수락 시 두 책을 함께 예약하고 관련 경쟁 신청을 거절 처리하며, 양쪽의 완료 확인 후 두 책을 완료 처리합니다. 동시성 보장은 운영 DB 트랜잭션으로 옮겨야 합니다.

표지는 저작권 이미지 대신 내장 타이포그래피 디자인을 제공하며 JPG/PNG/WebP 업로드·미리보기·삭제를 지원합니다. 외부 AI 키나 서비스를 사용하지 않습니다.

## 확인 결과

도메인 테스트: 중복 신청, 소유권, 수락 전후 연락처 권한, 경쟁 신청 마감, 예약, 양쪽 완료, 거절·취소, 추천 제외, 직렬화 통과.

브라우저 직접 확인: 데모 로그인, 책 등록, 제목 검색, 교환 신청, 상대 계정 로그인 및 수락, 연락처 공개, 양쪽 완료 확인, 새로고침 후 완료 상태 유지.
