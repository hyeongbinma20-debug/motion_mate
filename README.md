# 책잇 — 책과 사람을 잇는 책 교환 서비스

프로젝트를 시작하기 전에 [공용 DB 연결 안내](CLOUD.md)와 [AI 설정 안내](AI_SETUP.md)를 읽어주세요. 기존 docs/SETUP.md는 초기 Next.js 보일러플레이트 안내이며, 현재 배포 앱의 실행 방법은 아래와 같습니다.

## 프로젝트 개요
- 한 줄 소개: 읽지 않는 책을 등록하고, 다른 독자의 책을 찾아 서로 교환하는 웹앱입니다.
- 누구를 위한 앱인가: 읽은 책을 나누고 새로운 책을 만나고 싶은 독자.
- 어떤 상황에서 쓰는가: 책장을 정리하거나 원하는 책을 구매 대신 교환으로 구하고 싶을 때.

## 주요 기능
| 과제의 꼭 있어야 하는 기능 | 화면(프론트엔드) | API(백엔드) |
| --- | --- | --- |
| 1. 회원가입·로그인과 프로필 관리 | 이메일 회원가입·로그인, 프로필 수정, 로그아웃 | Supabase Auth, 소유권을 검증하는 프로필 저장 RPC |
| 2. 책 등록·조회·수정·삭제 | 사진 업로드, 분야·상태 입력, 제목·저자 검색, 상세 화면 | Supabase PostgreSQL, bookit_write_book / bookit_write, RLS |
| 3. 책 교환 신청과 완료 관리 | 내 책 선택, 신청, 수락·거절·취소, 교환 메모, 양쪽 완료 확인 | DB 트랜잭션 기반 신청·예약·상태 전환, 수락 당사자 연락처 조회 |

더 만든 기능:
- AI가 표지의 제목·저자를 읽고 Google Books의 실제 도서를 조회합니다. 후보를 선택하면 제목·저자·ISBN·출판사·분류·쪽수·소개가 바로 입력됩니다. 수정·확인 후 등록하며, 없는 정보는 추측하지 않습니다.
- 등록된 교환 가능 매물만 사용하는 대화형 AI 추천: 필수·선호 조건 구분, 한 번에 하나씩 질문, DB 후보 ID 검증, 추천 이유, 조건 완화.
- 관심목록, 최근 본 책 30권, 12권씩 화면 페이지 구분, 맞춤 장르·상태, 임시 저장.
- 이미지 압축·지연 로딩·묶음 조회, 모바일 메뉴, 오른쪽 아래 책 등록 버튼, 표지 호버 확대.
- 교환 수락 시 다른 신청 자동 마감, 합의 취소, 등록 종료·재등록.
- 실시간 채팅 대신 수락 후 연락처와 교환 메모로 약속을 관리합니다.

## 기술 스택
- 프론트엔드: HTML, CSS, JavaScript ES Modules, 해시 라우팅.
- 백엔드: Supabase Auth, PostgreSQL RPC·RLS, Supabase Edge Functions(Deno/JavaScript·TypeScript).
- AI·외부 데이터: 학교 BAZE Gateway의 gpt-5.6-luna, Google Books API. 키는 서버 Secrets에만 등록합니다.
- 데이터(어디에, 무엇을): 책·프로필·교환 신청·연락처·관심목록·도서 부가정보는 Supabase에 저장합니다. 연락처는 별도 권한으로 보호합니다. 최근 본 기록은 기기별 localStorage, 작성 중 임시 내용은 계정별 sessionStorage에 저장합니다.
- 배포: GitHub Pages와 GitHub Actions. Node.js는 로컬 정적 서버·검증·함수 소스 생성에 사용합니다.

## 실행 방법
1. Node.js 22 이상을 준비하고 저장소를 내려받아 server.mjs가 있는 폴더에서 터미널을 엽니다.
2. `node server.mjs`를 실행합니다. 정적 앱 실행에 별도 패키지 설치나 Next.js 빌드는 필요하지 않습니다.
3. 브라우저에서 http://127.0.0.1:4173/ 에 접속합니다. 자체 Supabase 프로젝트를 사용할 경우 CLOUD.md의 DB·인증·공개 연결 설정과 AI_SETUP.md의 함수 배포·키 등록 절차를 따르세요.

서버 환경 변수 예시: [supabase/functions/.env.example](supabase/functions/.env.example). BAZE_API_KEY와 GOOGLE_BOOKS_API_KEY의 실제 값은 Supabase Secrets에만 저장합니다.

배포 주소: https://hyeongbinma20-debug.github.io/motion_mate/

## AI 활용 내역
- 사용한 도구: Codex로 구현·디버깅·테스트·배포를 진행했습니다. 서비스 내부 AI에는 BAZE Gateway를 사용하고 도서 사실 정보는 Google Books에서 조회합니다.
- 주요 프롬프트(실제 입력 문구):
  > 책 교환 서비스 웹앱을 만들어줘.

  > 지금 ai가 책 정보를 사진보고 찾아주잖아 그걸 기반으로 선택하면 따로 사용자가 적지않고 입력되게해줘
- AI가 만든 것 / 사람이 고친 것: AI는 화면·서버 함수·SQL·테스트를 구현했습니다. 사람은 서비스 요구사항, 디자인 방향, 개선 우선순위를 결정하고 실제 사용 피드백과 API 발급·등록을 진행했습니다. 피드백에 따른 코드 수정은 Codex로 반영했습니다.
- 결과를 확인한 방법: 회원·책·교환 상태·권한·입력·AI 후보 검증 테스트, 실제 DB의 롤백 테스트, 운영 앱에서 실제 AI 추천과 도서 조회·선택 자동 입력을 확인했습니다. 사진 인식 정확도 전체와 Lighthouse 점수는 별도 측정이 필요합니다.

## 팀원 역할
(이름·학번 없이 역할만)
- 기획: 사용자 문제 정의, 필수 기능과 디자인 방향 결정.
- 프론트엔드: 등록·검색·프로필·교환·추천 화면, 반응형 UI와 상태 안내 구현.
- 백엔드: 인증, DB 권한·교환 트랜잭션, 외부 API와 호출 제한 구현.
- 검증: 사용자 흐름 확인, 오류 재현, 자동 테스트와 DB·배포 확인.

## 아쉬운 점과 다음에 할 일
- 현재 목록은 최대 1,000권의 가벼운 정보를 읽고 화면에서 12권씩 나눕니다. 서버에서 검색·정렬·페이지 조회까지 처리하도록 개선해야 합니다.
- 최근 본 책은 기기별 기록이며 다른 기기와 동기화되지 않습니다.
- 도서 API에 없는 책이나 불명확한 표지는 직접 입력이 필요합니다.
- 로그인한 모바일 첫 화면의 Lighthouse 성능을 3회 측정하고 중간값을 기록할 예정입니다. 측정하지 않은 점수는 기재하지 않습니다.
- 여러 실제 사용자·대량 데이터 환경의 부하 검증, 메일 발송 설정과 AI 비용 모니터링을 보완할 예정입니다.
