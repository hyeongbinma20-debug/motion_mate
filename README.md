# 책잇 — 책과 사람을 잇는 책 교환 서비스

프로젝트를 시작하기 전에 [docs/SETUP.md](docs/SETUP.md)를 먼저 읽으세요. 현재 앱의 DB·인증 연결은 [CLOUD.md](CLOUD.md), AI 연결은 [AI_SETUP.md](AI_SETUP.md)를 참고하세요. 실제 배포 앱의 실행 방법은 아래에 정리했습니다.

## 프로젝트 개요

- **한 줄 소개:** 읽지 않는 책을 등록하고 다른 독자의 책과 교환할 수 있는 독서 커뮤니티 웹앱입니다.
- **누구를 위한 앱인가:** 읽은 책을 나누고 새로운 책을 만나고 싶은 독자입니다.
- **어떤 상황에서 쓰는가:** 책장을 정리하거나, 원하는 책을 구매 대신 교환으로 구하거나, 취향에 맞는 책을 추천받고 싶을 때 사용합니다.

## 주요 기능

| 과제의 꼭 있어야 하는 기능 | 화면(프론트엔드) | API(백엔드) |
| --- | --- | --- |
| 1. 책 등록·조회·수정·삭제 | 표지 업로드, 책 정보 입력, 검색·필터, 목록·상세 보기, 수정·삭제 | Supabase DB에 저장하고, 서버에서 소유권·입력값·교환 상태를 확인한 뒤 처리 |
| 2. 교환 신청과 진행 관리 | 내 책 선택, 교환 신청, 수락·거절·취소, 연락처 확인, 교환 메모, 양쪽 완료 확인 | 신청 상태 저장, 두 책 동시 예약, 경쟁 신청 마감, 당사자 권한 확인, 양쪽 완료 처리 |
| 3. 회원가입·로그인과 프로필 관리 | 이메일 회원가입·로그인, 로그아웃, 프로필 수정, 내 책과 신청 내역 확인 | Supabase Auth와 사용자별 데이터 접근 정책 적용 |

**더 만든 기능:**

- **사진 기반 책 정보 자동 입력:** AI가 표지에서 제목·저자를 읽고 Google Books에서 실제 도서를 조회합니다. 후보를 선택하면 제목·저자·ISBN·출판사·분류·쪽수·소개가 바로 입력됩니다.
- **대화형 AI 추천:** 원하는 장르·분위기·분량·지역·교환 조건을 파악하고, 실제 등록된 교환 가능 책만 추천합니다. 필수 조건과 선호 조건을 구분합니다.
- **관심목록:** 마음에 드는 책을 저장하고 다시 확인할 수 있습니다.
- **최근 본 책:** 최근 확인한 책을 최대 30권까지 기기별로 기록합니다.
- **목록 페이지 구분:** 한 화면에 12권씩 표시합니다.
- **상세 정보 입력:** 기본 분야·상태 외에 세부 장르와 사용 흔적을 직접 작성할 수 있습니다.
- **임시 저장:** 작성 중인 책 정보와 사진을 같은 계정·탭에서 복원할 수 있습니다.
- **모바일 UI:** 하단 메뉴와 오른쪽 아래 책 등록 버튼을 제공합니다.
- **로딩 개선:** 사진 압축, 화면 근처 이미지 지연 로딩, 사진 묶음 조회와 중복 요청 방지를 적용했습니다.

## 기술 스택

- **프론트엔드:** HTML, CSS, JavaScript ES Modules, 해시 기반 라우팅
- **백엔드:** Supabase Auth, PostgreSQL, DB 함수(RPC), 접근 정책(RLS), Supabase Edge Functions
- **AI·외부 API:** 학교 BAZE Gateway의 `gpt-5.6-luna`, Google Books API
- **배포:** GitHub Pages, GitHub Actions
- **데이터(어디에, 무엇을):**
  - Supabase: 책, 프로필, 교환 신청, 연락처, 관심목록, 도서 부가정보
  - localStorage: 기기별 최근 본 책 기록
  - sessionStorage: 계정별 작성 중 임시 내용
  - Supabase Secrets: AI·도서 검색 API 키

연락처는 별도 접근 정책으로 보호하며, 교환이 수락된 당사자에게만 표시합니다.

## 실행 방법

1. **Node.js 22 이상**을 준비하고, 저장소를 내려받아 `server.mjs`가 있는 프로젝트 폴더에서 터미널을 엽니다.
2. 다음 명령으로 로컬 서버를 실행합니다.

   ```bash
   node server.mjs
   ```

3. 브라우저에서 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)에 접속합니다.

현재 정적 앱을 실행하는 데 별도의 패키지 설치나 Next.js 빌드는 필요하지 않습니다. 자체 Supabase 프로젝트를 사용하려면 `CLOUD.md`의 DB·인증 설정과 `AI_SETUP.md`의 함수 배포·키 등록 절차를 따릅니다.

서버 환경 변수 예시는 [supabase/functions/.env.example](supabase/functions/.env.example)에 있습니다. 실제 키는 코드에 넣지 않고 Supabase Secrets에 등록합니다.

**배포 주소:** [책잇 서비스 바로가기](https://hyeongbinma20-debug.github.io/motion_mate/)

- **주요 프롬프트(실제 입력 문구):**

  > 책 교환 서비스 웹앱을 만들어줘.

  > 기존의 기능과 내용을 유지하고 마우스 커서를 책 사진위에 올렸을때 호버기능을 추가해서 당근마켓처럼 살짝 확대되게 만들어줘

  > 지금 ai가 책 정보를 사진보고 찾아주잖아 그걸 기반으로 선택하면 따로 사용자가 적지않고 입력되게해줘

- **AI가 만든 것 / 사람이 고친 것:**
  - AI는 화면, 서버 함수, DB SQL, 입력 검증, 테스트 코드를 구현했습니다.
  - 사람은 서비스 요구사항, 디자인 방향, 개선 우선순위를 결정하고 실제 사용 피드백과 API 발급·등록을 진행했습니다.
  - 사용자 피드백에 따른 코드 수정은 Codex로 반영했습니다.

- **결과를 확인한 방법:**
  - 책 등록·수정·삭제와 교환 상태 전환 테스트
  - 중복 신청, 타인 수정, 연락처 접근 권한 테스트
  - 실제 DB에서 테스트 후 롤백하는 검증
  - 운영 앱에서 실제 AI 추천, 도서 검색, 후보 선택 자동 입력 확인
  - 390px 모바일·1280px PC 화면의 가로 넘침 확인
  - 사진 묶음 조회, 로그인 만료 처리와 기존 기능 자동 테스트

## 아쉬운 점과 다음에 할 일

- 현재 목록은 최대 1,000권의 가벼운 정보를 읽고 화면에서 12권씩 나눕니다. 검색·정렬·페이지 조회를 DB에서 직접 처리하도록 개선할 계획입니다.
- 최근 본 책 기록은 기기별로 저장되므로 다른 기기와 동기화되지 않습니다.
- 도서 API에 없는 책이나 불명확한 표지는 직접 입력이 필요합니다. 다양한 실제 표지로 인식 정확도를 추가 검증할 계획입니다.
- 로그인한 모바일 첫 화면의 Lighthouse 성능을 3회 측정하고 중간값을 기록할 예정입니다.
- 여러 사용자가 동시에 사용하는 환경과 대량 데이터에 대한 부하 검증이 필요합니다.
- 이메일 발송 설정과 AI 사용 비용 모니터링을 보완할 계획입니다.
